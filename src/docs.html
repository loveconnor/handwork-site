Install and configure Handwork.

The npm package supports macOS on Apple Silicon and Windows on x64 and ARM64. Windows support is experimental. You need npm and access to a model provider.

01Quick start

# Install Handwork
npm install -g handwork

# Open a project
cd /path/to/your/project
handwork

Run /provider in Handwork to connect a provider. Run /model to choose a model.

Read the Windows support status and known limitations. Windows x64 has native CI coverage; Windows ARM64 is cross-compiled.

Check permissions first.

Run /permissions. The default auto mode reviews sensitive actions that no rule has approved. It can still approve an action, so it is not read only.

02Model providers

Handwork supports OpenAI, Anthropic, Gemini, xAI, DeepSeek, Mistral, Groq, Together AI, Fireworks AI, OpenRouter, MiniMax, and Ollama.

Run /provider, choose a provider, and enter its key. The input masks typed and pasted text. Press Enter to save the key and connect. Press Escape to cancel. Ollama can connect to your server without an API key.

The provider controls model access and billing. The official Codex and Copilot adapters run the provider's agent engine. They do not use Handwork's native tools, sessions, or permission checks.

03First task

Name the change and the checks you want Handwork to run.

Fix the failing parser test. Keep the change focused.
Run the parser tests and report the result.

Use ask to run one request without opening the interactive interface.

handwork ask "Explain this project's entry points"
handwork ask --json "Review the current changes without editing files"

The second prompt tells the model not to edit. It does not change tool permissions. Check the diff and command results after every coding task.

04Permissions and data

ModeBehavior
askPrompts before sensitive actions that no rule has approved.
autoReviews sensitive actions that no rule has approved. This is the default.
full-accessTurns off Handwork's permission checks.

Run /permissions ask to require prompts. Use /allowlist to manage saved rules. If auto mode returns a caution, Handwork holds the action instead of opening a prompt.

Cloud providers receive task data.

A request can include your prompt, code excerpts, tool results, and conversation history. Read the provider's data policy before sending private code. Handwork stores native API keys in files that only your account can read. It does not encrypt them at rest.

Permission checks do not isolate the process from the operating system. They also do not prove that generated code is correct.

05Commands

/newStarts a session.

/compactSummarizes the conversation in a new context window.
/skillsLists and manages skills.
/mcpManages MCP servers and project trust.

Run handwork --help in your shell for the full command list. Run handwork doctor to check the local setup. Run handwork update to update a global npm installation, then restart Handwork.

06Saved sessions

handwork sessions
handwork session resume last

Handwork stores native sessions in ~/.handwork/sessions. A resumed session restores the conversation. It does not restore old file contents or running programs. Check the workspace after an interrupted task.

Run handwork ask --no-save "Your task" when you do not want to save the request. Provider runtime sessions use the provider's storage.

07Images and diagrams

Added in v{{HANDWORK_VERSION}}. Handwork displays local images, SVG drawings, and supported Mermaid diagrams in the interactive conversation. Full-resolution graphics depend on your terminal's image support.

Try a diagram

Paste this prompt into Handwork. Ask for a fenced mermaid or svg block so Handwork can recognize the drawing.

Return only a fenced mermaid block, without tools or explanation.
Create a flowchart: Open project -> Run tests -> Tests pass?
If yes, finish. If no, fix the code and run tests again.

Flowcharts, state diagrams, sequence diagrams, and pie charts are supported. Other types, including class diagrams, Gantt charts, and entity-relationship diagrams, stay as code. Layout and text use Handwork's own renderer and may differ from Mermaid's browser output.

Show a local image

Ask Handwork to return a Markdown image on its own line, for example:

![Test results](out/results.png)

The file must exist when the message arrives. Relative paths start from the directory where you launched Handwork. PNG, JPEG, GIF, and WebP are supported; animated formats show their first frame. Attached images also appear as thumbnails under your prompt.

Choose a terminal

Seeing SVG source there is the expected fallback. Use a terminal with a supported graphics protocol for the rendered drawing.

Enable images in VS Code

Add these values to your VS Code settings, then start a new integrated terminal and restart Handwork:

{
  "terminal.integrated.enableImages": true,
  "terminal.integrated.gpuAcceleration": "auto"
}

See VS Code's terminal image documentation for host requirements.

Controls and limits

Press Control-O to open the conversation viewer. Use the trackpad or Page Up / Page Down to scroll. In Apple Terminal, enable View > Allow Mouse Reporting for trackpad scrolling.

To keep image labels and diagram source as text, start Handwork with:

HANDWORK_IMAGES=off handwork

Remote image URLs are off by default. SVG supports common shapes, paths, gradients, and text, but not every browser feature: masks, filters, clipping paths, patterns, and embedded images are not drawn. SVG text uses Handwork's stroke font rather than the font named in the file.

08Build from source

The repository uses Zig 0.16.0.

git clone https://github.com/loveconnor/handwork.git
cd handwork
zig build
./zig-out/bin/handwork --help

The native agent can call model APIs without the JavaScript adapters. The official runtime adapters also need npm ci and Node.js 22.12 or newer, or Node.js 20.19 or newer. The project does not claim support for every source build target.
